# 잡은 사진 변신 + 펫 자리 — 계획 초안 (2026-11-11)

운영자 결정 (2026-11-11):
- 잡은 진짜 사진을 그대로 쓰지 않는다. 변신 방식은 전부 옵션으로 둔다.
- 기본은 **AI 변신**이다. 잡을 때 동의를 한 번 받는다. 하루 한도는 기기당 5장, 전체 100장이다. 한도를 넘으면 기기 안 털뭉치 변신으로 바꾼다.
- AI 스타일 두 가지:
  - 3a 털뭉치: 우리 녀석 그림체.
  - 3b 3D 피규어: 그 동물·사람 모습 그대로.
- **둘 다:** 평소에는 피규어 그림을 쓴다. "3D로 만들기"를 누르면 돌려 볼 수 있는 진짜 3D 모델(GLB)을 만든다.
- 툰 필터(2번)는 더 다듬어서 옵션으로 남긴다.
- 원래 사진은 도감 상세에만 작게 남긴다.
- 시안: `mockups/transform.html`. 시안 그림은 Codex 이미지 생성으로 만들었다. 게임 서버는 Codex 를 못 쓰므로 이미지 API 를 따로 쓴다.

## 흐름

```
잡음 ─▶ 기기 안 털뭉치(1번)가 즉시 등장
     └▶ (동의·한도 OK) Worker /transform {kind, style, cut PNG}
            └▶ 이미지 AI ─▶ PNG ─▶ 녀석·도감 그림 교체 (10~30초)
도감 상세 "3D로 만들기" ─▶ Worker /to3d ─▶ image→3D API (1~3분, 작업 id 로 폴링)
            └▶ GLB ─▶ IndexedDB ─▶ AR 에서 GLTFLoader 로 세움
```

## 단계

| # | 할 일 | 메모 |
|---|---|---|
| 1 | 툰 필터 다듬기 | 얼룩을 줄인다(큰 패치 병합·가장자리 보존). 얼굴은 작은 패치를 유지한다. |
| 2 | 이미지 API 고르기 | Gemini 2.5 Flash Image vs gpt-image. 같은 사진 3장으로 품질·지연·단가를 비교한다. `ai-hub/llm-registry.toml` 에 `dot-lab.catch_transform` 을 등록한다. |
| 3 | Worker `works/2026-11-09-catch/worker` | `/transform`, `/to3d`. KV 카운터로 기기·전체 한도를 건다. 사진은 저장하지 않는다. 키는 Worker secret 에 둔다(운영자 위저드). 배포는 Pages 와 따로 한다(memory: Pages ships before the Worker). |
| 4 | 게임 연결 | 동의 시트, 털뭉치 → AI 그림 자동 교체, 도감에 원본 작게, 설정에서 스타일 고르기(3a/3b/툰/털뭉치). |
| 5 | 3D 모델 | image→3D API(Tripo/Meshy 등)를 비교한다. GLB 를 AR 에 세우고 도감에서 돌려 본다. 한도는 기기당 하루 1개. |
| 6 | 펫 자리 | `mockups/refs.html` 에서 운영자가 번호로 고른 자리를 Android 앱에 붙인다. |

비용 상한: 이미지는 하루 약 $4, 3D 는 하루 약 $5 다. 넘으면 다음 날까지 기기 안 변신만 쓴다.
