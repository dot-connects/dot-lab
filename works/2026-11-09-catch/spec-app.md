# 「우리 집 몬스터 잡기」 앱 — 설계 (2026-11-12)

웹 작품(`site/`)을 접고 **안드로이드 네이티브 앱 하나**로 다시 만든다. 운영자와 2026-11-11~12 브레인스토밍에서 정한 것만 적는다.
시안: `mockups/catch-motion.html`(움직이는 영상 판정) · `mockups/claw-endings.html`(마무리 3종, **2 캡슐 채택**) ·
`mockups/pet-moves.html`(펫 동작·자리). AI 동작표 실물: `out/ai/sheet/{cat,dog}.png`.

## 1. 한 줄

카메라 화면 속 우리 집 강아지·고양이·사람과 바닥 위 작은 털 녀석을 **인형뽑기 집게로 뽑아** 캡슐에 담고 도감에 모은다.
털 녀석은 바로 폰 화면 가장자리에 사는 **펫**이 되고, 진짜 녀석은 AI 그림을 사면 펫이 된다.

## 3. 화면과 흐름

```
[뽑기]  앱을 열면 바로
  카메라 + 실시간 윤곽(진짜) + ARCore 바닥 위 작은 털 녀석
  집게 끌다 놓기 ─▶ 판정 ─┬ 실패: 미끄러짐, 알림 1초
                          └ 성공: 캡슐 → 굴러감 → 도감 +1
        └──────── 어느 쪽이든 바로 다음 뽑기 ────────┘
     │ "도감 N"
     ▼
[도감]  캡슐 칸 그리드 (진짜 = 오린 사진, 털 녀석 = 그림)
     ▼
[녀석 상세]  모은 모습들 (앞·옆·누움·뒤…)
  털 녀석 ─▶ "펫으로 쓰기" (무료)
  진짜 녀석 ─▶ AI 미리보기(털뭉치·피규어, 하루 5장) ─▶ "펫으로 사기" (잠김)
     ▼
[펫]  켜기/끄기, 자리 고르기 (아래 줄 · 왼쪽 벽 · 오른쪽 벽 · 아이콘 뒤)
```

**모습 모으기는 유지한다.** 같은 녀석을 다른 자세로 또 뽑으면 모습 칸이 찬다.
- 진짜 녀석: 각도 판정은 웹 버전(`brief.md` "모습 모으기")을 따른다.
- 털 녀석: 뽑은 순간 보던 방향이 모습이 된다.

## 4. 구조

```
app (Kotlin, minSdk 34)
├─ catch/      CameraX 프레임 → Segmenter → 윤곽 추적(놓친 프레임 최대 4개 유지)
│              Claw 상태 기계(aim/down/grip/up/fall/capsule) — 순수 Kotlin, 판정·확률 단위 테스트
│              Compose Canvas: 카메라 위 레일·집게·캡슐·알림
├─ ar/         ARCore 세션, 바닥면 앵커, 털 녀석 = 미리 구운 스프라이트 빌보드
│              (8방향 × 숨쉬기 프레임; 3D 엔진 없이 OpenGL ES 사각형 + 그림자 원)
├─ dex/        Room DB: Creature(id, kind, name, type, catchAt), Pose(creatureId, label, png 경로, grade)
│              진짜 녀석 PNG 는 앱 내부 저장소에만
├─ ai/         Worker 호출(미리보기·동작표), 기기 ID, 동의 1회
├─ billing/    Play Billing (출시 전: 버튼 잠금 + 운영자용 디버그 해제 플래그)
└─ pet/        기존 `app/` 의 PetService(오버레이) + Behaviour 상태 기계를 옮겨 확장
               아이콘 뒤 = WallpaperService(라이브 배경화면)
```

- **진짜 녀석 찾기(Segmenter):** 웹의 DeepLab 은 11-12 고양이 영상 120프레임 중 21프레임을 아예 놓쳤다.
  - 첫 단계 스파이크에서 같은 영상으로 후보를 비교해 고른다. 후보: MediaPipe DeepLab(Android), ML Kit Subject Segmentation, 그 밖의 COCO 인스턴스 분할 모델.
  - 라이선스가 AGPL 인 모델(예: Ultralytics YOLO)은 쓰지 않는다. 앱 코드 공개 의무가 생긴다.
- **털 녀석 그림:** `site/js/creatures.js` 3D 털 녀석을 헤드리스 Chrome 으로 구워 PNG 로 만든다. 굽는 것은 뽑기용 8방향과 펫 동작 6종이다. 앱은 그 그림만 싣는다. 털 셰이더를 네이티브로 다시 만들지 않는다.
- **카메라 프레임 → 윤곽:** 판정에는 낮은 해상도 마스크(웹은 90×160)로 충분하다. 오려 내기는 잡은 순간의 고해상도 프레임 한 장으로 한 번 더 한다(웹 `refine.js` 방식).

## 5. 펫 동작 규칙

| 언제 | 자리 | 동작 |
|---|---|---|
| 평소, 5~8초마다 무작위 | 아래 줄 | 숨쉬기 · 몇 걸음 · 멈칫 갸웃("?" 작게) |
| 평소 | 벽 | 조금 오르내리기 · 멈춰 숨쉬기 |
| 평소 | 아이콘 뒤 | 아이콘 사이를 천천히 걷기 |
| 한 번 누름 | 어디든 | 웃으며 콩콩 |
| 두 번 누름 | 어디든 | 제자리 작은 춤 3초 |
| 몇 분 안 만짐 · 밤 · 충전 중 | 지금 자리 | 그 자리에서 잠, 누르면 깸 |
| 꾹 눌러 끌기 | - | 대롱대롱, 놓으면 가장 가까운 자리에 붙음 |

그림 칸: 앞 · 웃음 · 옆걸음 A · 옆걸음 B · 누워 자기 · 몸 말고 자기.
- 벽에서는 옆걸음 칸을 90도 돌려 쓴다.
- 털 녀석은 같은 6칸을 3D 에서 굽는다.
- 진짜 녀석은 AI 동작표 한 장(3×2)을 잘라 쓴다. 초록 배경은 앱이 지운다.

## 6. AI (서버 = 기존 Cloudflare Worker `dot-lab-catch`)

| 요청 | 모델 · 품질 | 크기 | 한도 | 원가(실측) |
|---|---|---|---|---|
| 미리보기 (털뭉치 / 피규어) | gpt-image-2.6-flare · low | 1024² | 기기 5 · 전체 30 / 일 | 약 3센트 |
| 동작표 (구매 후) | gpt-image-2.6-flare · medium | 1536×1024 | 구매 1건당 1회 + 실패 재시도 1회 | 약 4.3센트 |

- Worker 를 Gemini 에서 OpenAI images/edits 로 교체한다. 키는 Worker secret `OPENAI_KEY`(11-12 wizard 로 이미 넣음).
- `ai-hub/llm-registry.toml` 의 `lab.catch_transform` chain 도 바꾼다(워크스페이스 규칙).
- 5xx 는 한 번 재시도한다. 11-12 시험에서 5번 중 3번이 500 이었다.
- 사진은 저장하지 않는다. OpenAI 에 보내는 건 오린 PNG 한 장뿐이다.
- 동작표 요청은 Play 구매 토큰을 Worker 가 검증한 뒤에만 받는다. 출시 전에는 운영자 디버그 토큰만 통과한다.
- OpenAI 충전금이나 월 예산이 다 되면 "AI 그림을 잠시 못 그려요"를 띄운다. 미리보기는 다음 날 다시 된다.
  구매했는데 실패하면 결제를 확정하지 않는다(Play 구매 미확인 → 자동 환불).

## 7. 검수

- **틀리면 비싼 곳만 단위 테스트(JVM):** 집게 판정·확률, 윤곽 추적(놓침 유지), 캡슐 상태 기계, 펫 Behaviour, 하루 한도, 구매 잠금.
- **실폰:** 이 PC 에는 adb 가 없다. 단계마다 APK 를 SendUserFile 로 보내고 운영자가 실폰에서 판정한다. 화면 녹화가 있으면 같이 받는다.
- **세그먼트 회귀:** `research/claw-media/kitten.webm` 앞 10초를 고정 입력으로, 놓친 프레임 수를 기록해 비교한다.
- 통과 기준(채널 규칙): 운영자가 직접 해 보고 한 번 더 하고 싶은가.
