# 여행 한 권 — 사진 고르기·책 만들기 다시 보기 (2026-11-27)

코드는 건드리지 않은 검토 문서. 읽은 것: `pipeline.dart`, `core/prefilter·plan_check·scenes`, `worker/src`, 테마 7개 틀 목록, 시안 r21 C, spec·plan-r2.
**(가정)** 표시는 재 보지 않은 숫자다. 환율은 1달러 1,400원(가정).

## 결론

1. **지금 사진을 고르는 건 AI가 아니라 "선명도 순" 규칙이다.** 2,295장 중 AI가 보는 건 60장(2.6%)이고, 그 60장을 폰이 "날마다 선명한 순"으로 뽑는다. AI는 그중 절반쯤만 덜어낸다. 고르기가 별로였던 원인은 여기다(아래 0절).
2. **초안의 큰 방향(장면 묶기 → 넓게 훑기 → 규칙 → 최종)은 맞다. 세 가지를 바꾼다.** ① 밀착 인화지(여러 장을 한 장에 모은 그림)는 만들지 않는다 — gpt-5.4는 그림 값을 넓이로 매겨서 모아 붙여도 싸지지 않는다. 256px 낱장을 장면별로 묶어 보낸다. ② 훑기는 한 번에 보내지 않고 5~6묶음을 동시에 보낸다(값의 대부분이 "답 쓰는 글자"라 한 번에 보내면 2~3분 걸린다). ③ 훑기 모델은 작은 것(gpt-5.4-mini)으로. 그래야 초안의 "100원"이 맞는다. gpt-5.4로 하면 약 400원(가정).
3. **AI를 더 쓰기 전에 폰 규칙부터 고친다(추가 비용 0원).** 장면 안에서 서로 비교한 선명도, 많이 찍은 곳에 더 많은 자리(√장수), 연속 컷 살리기, 얼굴 수(폰 안에서 무료). 이것만으로 나아지는 몫이 가장 크다고 본다. 그다음에 훑기 AI를 붙인다.
4. **선별 규칙은 운영자 여행 사진을 PC에 한 번 복사해 PC에서 다듬는다.** 폰 빌드 없이 "옛 방식 대 새 방식"을 한 화면에 나란히 놓고 운영자가 고르면, 하루에 수십 번 고칠 수 있다.
5. **고르는 동안 화면 = 모자이크 C + "여행을 처음부터 다시 훑는다".** 칸이 날짜 순으로 실제 사진으로 채워지고, 그때그때 진짜 숫자·발견이 한 줄씩 뜬다. 가짜 타이머는 없앤다. 나가도 계속되고 알림으로 부른다.
6. **책 쪽은 틀이 이미 있다. 재료가 안 갔을 뿐이다.** 먹은 것 모음·연속 컷 틀이 테마마다 대부분 있는데, 고르기가 비슷한 사진을 다 버려서 쓸 수 없었다. 고르기가 "묶음(연속 컷·먹은 것)"을 만들어 넘기면 된다. 새로 그릴 쪽은 **네 컷(인생네컷 모양) → 숫자 쪽 → 다닌 길 그림** 순.
7. **만드는 동안 화면 = 표지부터, 실제 쪽이 하나씩.** 1단계는 이미 있는 재료(날마다 한 줄, 고른 사진)로, 2단계는 AI 답을 흘려 받아 진짜 쪽을 보여 준다. 지금의 "4단계 체크"는 시간으로 넘기는 가짜라 없앤다.
8. **한 권 더 만들게 하는 가장 센 지렛대는 책장의 "여행 추천"이다.** 폰이 갤러리에서 여행 같은 날짜 묶음을 찾아 "8월 강릉 · 834장 [만들기]"를 보여 주면 날짜 고르기가 사라진다.

## 1. 사진 고르기 시퀀스

### 1-1. 흐름

```
[폰·무료] ① 목록: 시각만 먼저 (DB 한 번 조회, 수만 장도 몇 초 (가정))
          ② 장면 나누기: 20분 넘게 쉬었거나 300m 넘게 움직이면 새 장면 (값은 실측으로 조정)
             장면의 장수 = 그곳이 얼마나 좋았나
          ③ 장면 순서대로 256px 미리보기 재기: 흐림·어두움·캡처 빼기
             똑같은 연사(1초 안)는 한 장으로 / 1~15초 간격 3장 이상 = "연속 컷" 후보로 보존
             얼굴 수·눈 뜸·웃음 (ML Kit — 구글의 폰 안 얼굴 찾기, 무료, 사진이 폰을 안 떠남)
          ④ 넓은 후보 ≤480: 장면마다 자리 = √장수 비례, 모든 장면 최소 1장,
             장면 안에서 시간대별로 나눠 "그 장면 안에서 상대적으로" 좋은 것
             ★즐겨찾기·꼭 넣을 사진·연속 컷·받은 사진은 무조건 포함
[AI 1 훑기] 256px 낱장을 장면별로 묶어 5~6묶음 동시 전송 (③이 끝난 날부터 바로 보냄 → 재기와 겹쳐 진행)
          → 장마다 종류·사람 수·점수(1~5)·눈 감음, 장면마다 "무엇을 한 곳"·그 장면 베스트
[폰·규칙] ⑤ 결선 ≈ 책 장수 × 2.2 (40장 책이면 90장): 아래 레시피의 최소·최대를 채움
             묶음 만들기: 먹은 것 4~6장, 연속 컷 3~4장
[AI 2 최종] 90장을 512px로 (지금의 /pick 그대로) → 책에 넣을 36~44장 + 표지 후보 3 + 묶음 확정 + 날마다 한 줄
[폰·검사] ⑥ checkPick 확장: 날·시간대·종류 최소가 빠졌으면 결선에서 점수순으로 채움
```

장면별로 묶어 보내는 이유: "이 비슷한 12장 중 뭐가 제일 낫나"는 사람이 고를 때 하는 바로 그 비교이고, 모델도 한 묶음 안의 상대 비교를 0~100 절대 점수보다 훨씬 잘한다.

"누구랑"이 혼자면 사람 몫을 풍경·디테일로 돌리고, 가족이면 아이·부모 컷을 올린다. "사람 사진" 옵션(섞어서/풍경/사람)은 이 표의 몫을 움직이는 손잡이가 된다.

### 1-5. 코드가 할 일, AI가 할 일

원칙: **AI는 보고 이름표·점수를 붙이고, 코드는 세고 보장한다.**

| 코드(규칙) | AI(판단) |
|---|---|
| 장면 나누기, 장면별 자리 수 | 무엇이 찍혔나(음식·명소·활동·동물·특이함) |
| 날·시간대 빠짐없이, 종류별 최소·최대 | 비슷한 것 중 무엇이 나은가(표정·구도) |
| 똑같은 연사 한 장으로, 연속 컷 후보 찾기 | 그 연속 컷이 귀여운가, 어느 3~4장인가 |
| 장수 상한, 꼭 넣을 사진, 비용 상한 | 표지 후보, 날마다 한 줄, 영상 구간 |
| AI 답 검사하고 모자란 종류 채우기 | 동행 두 사람을 겉모습으로 구분해 균형 맞추기 |

- **연속 컷("딱딱딱")**: 1초 안 + 거의 같음 = 연사(한 장만). 1~15초 간격으로 3장 이상 이어지고 배경이 같으면 연속 컷 후보. 얼굴이 있으면 가산. 경계값은 운영자 사진의 "간격·닮음" 분포를 보고 정한다. 후보 4~8장을 최종 AI에 나란히 보여 주고 "포즈가 달라 재미있나, 어느 3~4장"을 묻는다.
- **서로 찍어 준 사진**: 얼굴 1개 + 얼굴이 화면 높이의 5~35%(가정, 셀카는 더 큼) + 받은 사진 폴더. 누가 누군지는 최종 AI가 옷·겉모습으로 A/B를 나눠 수를 맞춘다. 얼굴로 사람을 알아보는 기능은 넣지 않는다.
- **영상**: 훑기엔 한 장면만, 최종에 오른 영상(≤4)만 지금처럼 4장면. 장면이 많이 찍힌 곳의 3~60초 영상 우선.
- **수만 장**: 시각은 한 번에 읽히므로 장면은 재기 전에 나온다. 재는 장수만 장면당 상한(예: 40 + 6√장수)으로 줄인다. 지금의 "전체를 시간 순으로 4,000장"은 없앤다.
- **AI 없이도**: ④의 폰 규칙 결과가 그대로 "AI 실패 시 책"이 된다. 지금의 선명도 순보다 훨씬 낫다.

### 1-6. 고른 사진 보기·둘 중 하나

- **고른 사진 보기**: 맨 위에 "풍경 11 · 같이 6 · 한 명 6 · 먹은 것 5 · 연속 컷 2묶음" 한 줄(왜 이렇게 골랐는지가 보인다). 묶음은 겹친 타일 하나로. [바꾸기] 후보는 "시간이 가까운 순"이 아니라 같은 장면의 점수순으로, [+]도 "그날 가장 선명한 것"이 아니라 다음 점수순으로. "가장 많이 찍은 곳 3곳 · 214장 중 5장 [더]" 줄을 둔다.
- **둘 중 하나**: 긴 기다림 직후에 막아서는 질문이라 보상이 늦어진다. 별도 화면을 없애고 고른 사진 보기 안의 "둘 중 하나" 표시 타일로 옮기길 권한다(안 눌러도 진행). 사람에게 물을 가치가 큰 건 비슷한 두 장보다 **표지 3장 중 하나**다.

### 1-7. 비용·시간 (전부 가정 — Worker 로그의 실제 토큰으로 바꿔 넣을 것)

그림 값(gpt-5.4 계열): 512×384 한 장 ≈ 231토큰, 256×192 ≈ 58토큰. "detail low"는 이 모델에서 값을 줄여 주지 않는다. 보내는 크기가 곧 값이다.

| 단계 | 들어감 | 나옴 | 값 |
|---|---|---|---|
| 지금 /pick (60장 512px) | 1.7만 | 6천 | 약 185원 |
| 훑기 480장 256px, mini | 3.2만 | 1.5만 | **약 125원** (gpt-5.4면 약 410원) |
| 최종 /pick (90장 + 영상 장면) | 2.9만 | 6천 | 약 225원 |
| /layout (지금 그대로) | 1.6만 | 1만 | 약 265원 |
| **한 권 합계** | | | 지금 약 450원 → 새 구조 약 615원 |

가격 1,500원에서 스토어 몫 15%를 빼면 1,275원이다. 무료 2권은 한 사람당 약 1,200원이 든다. 올리는 양: 256px 480장 ≈ 6~8MB(가정) — LTE에서 몇 초가 걸리는지 재야 한다.

시간(2,295장): 폰 재기 30~60초 + 훑기 20~40초(재기와 겹침) + 최종 30~60초 = **1분~2분 반**. 지금보다 짧아지지 않는다. 그래서 2절의 화면과 "나가 있기"가 필요하다. 최종 /pick의 추론 세기를 낮추면 절반쯤 줄 수 있다(/layout 실측: 낮음 66초 대 보통 128초).

## 2. 고르는 동안 화면

줄거리: **"여행을 첫날부터 다시 훑는다."** 모자이크 C의 칸이 날짜 순서로 채워진다. 장면 순서대로 재므로 실제 진행과 같다.

```
┌──────────────────────────┐
│ ✕                  1 / 2 │
│ 사진을 고르고 있어요       │
│ 1,240                    │ ← 실제로 살펴본 장수
│ 둘째 날 · 6월 13일         │ ← 지금 보고 있는 날
│ ▓▓▓▓▓▓▓▒▒▒░░░░ 1분쯤 남음  │ ← 3구간: 훑어보기 · 살펴보기 · 고르기
│ ┌──────────────────────┐ │
│ │ 모자이크: 칸 = 진짜 사진 │ │ 거른 칸은 사라지고 남은 칸이 커짐
│ │   ┌────────┐         │ │
│ │   │ 발견 카드│ ← 좋은 사진 한 장이 1.5초 커졌다 돌아감
│ │   └────────┘         │ │
│ └──────────────────────┘ │
│ "가장 많이 찍은 곳 · 성산 214장" ← 발견 한 줄 (2.5초씩)
│ 미리보기 412장만 AI로 보내요 … │
└──────────────────────────┘
```

| 때 | 실제로 하는 일 | 화면 | 발견 줄(진짜 값만, 없으면 건너뜀) |
|---|---|---|---|
| 0~3초 | 목록·장면 나누기 | 빈 모자이크에 날짜 칸막이 | "4일 동안 2,295장" · "가장 많이 찍은 날: 둘째 날 812장" · "영상 37개" |
| 훑어보기 | 재기 + 얼굴 | 칸이 날 순서로 채워짐, 거른 칸은 흐려지다 사라짐 | "흔들린 사진 312장은 뺐어요" · "사람이 나온 사진 640장" · "연달아 찍은 묶음 23개" · "가장 많이 찍은 곳: ○○ 214장" |
| 살펴보기 (AI 1) | 묶음이 하나씩 돌아옴 | 돌아온 날의 칸 위로 빛이 지나감, 발견 카드 | "먹은 것 38장" · "고양이 발견" · "둘째 날 오후 — 해변 물놀이"(AI가 본 장면 이름) |
| 고르기 (AI 2) | 결선 90장 → 책 | 90장만 남아 커지고 빛이 훑음 | "90장 중 책에 넣을 사진 고르는 중" |
| 끝 | | 고른 장만 또렷하게 | **[31장 보러 가기]** 버튼(자동으로 넘기지 않음) |

- **정직하게**: 타이머로 단계를 넘기지 않는다(지금 화면은 1.3초마다 넘기고, 12장을 48칸에 돌려 쓴다). 숫자는 전부 실제 값. 남은 시간은 초 단위 카운트다운이 아니라 "1분쯤 → 30초쯤 → 거의 다 됐어요"로, 폰 구간은 실제 속도로, AI 구간은 지난 실행의 중앙값으로 계산한다.
- **개인정보 줄도 정직하게**: 보내는 장수가 60 → 최대 480으로 늘어난다. "더 작게 줄인 미리보기 N장"으로 실제 수를 쓴다(열린 질문 1).
- **나가면**: 만들기에 이미 있는 "진행 알림"을 고르기에도 켠다 → "사진 고르는 중 1,240 / 2,295", 끝나면 "31장 골랐어요 · 보러 가기". 책장에는 만드는 중인 책이 진행 고리와 함께 놓인다. ✕는 "그만두기"가 아니라 "나가 있기"다.
- **꺼져도**: 잰 값과 AI 꼬리표를 사진 id별로 폰에 저장한다 → 다시 열면 이어서 하고, 다시 돈 내지 않는다. 같은 기간으로 두 번째 책을 만들 때는 거의 즉시다.
- 구현 메모: 칸은 위젯 수천 개가 아니라 재면서 얻은 16px 색 조각을 한 캔버스에 그린다.

## 3. 책 구성

**이미 있는 틀** (테마마다 23~26개):

| 필요한 쪽 | a | b | c | diary | mag | album | photo |
|---|---|---|---|---|---|---|---|
| 먹은 것 모음 | grid4·grid6 | e-specimen | eat | grid4 | grid4 | grid | six |
| 연속 컷(가로) | strip3 | e-strip | three-moments | strip3 | strip | column·stair | seq3 |
| 연속 컷(세로, 사람 포즈) | **없음** | **없음** | **없음** | **없음** | triptych | seq(정사각) | four |
| 두 사람 짝 | row | e-pair | entry-pair | pair | pair-text | pair-wide | duo |
| 다닌 곳(글) | — | index | day-route·places | — | toc | — | — |
| 다닌 길(그림)·숫자 쪽 | 없음 | 없음 | 없음 | 없음 | 없음 | 없음 | 없음 |

가로 띠 틀(strip3 등)은 가늘게 잘려서 사람 포즈 연속 컷에 쓰면 머리가 잘린다. 그래서 세로 연속 컷 틀이 빈칸이다.

**새로 그릴 쪽 (순서)**
1. **네 컷** — 세로 3~4칸을 같은 크기로 나란히, 좁은 간격, 글 한 줄. 인생네컷 문법이라 설명이 필요 없다. a·b·c·diary에 테마 옷만 입혀 추가.
2. **숫자 쪽** — "4일 · 2,295장 중 40장 · 12곳 · 가장 오래 머문 곳 ○○". 고르는 동안 띄운 발견을 그대로 책 끝에 싣는다(계산은 이미 돼 있다, AI 불필요).
3. **다닌 길 그림** — 지도 타일 없이 위치 점만 이은 선 + 장소 이름. 폰에서 그린다.

**고르기 → 엮기로 넘길 것 (새 디자인 없이 되는 것)**
- **묶음**: `연속 컷 [a,b,c,d]`, `먹은 것(둘째 날) [..]`, `짝 [풍경, 사람]`. 틀 목록(layouts.json)에 "이 틀은 연속 컷용/먹은 것용" 표시를 하나 달면, 코드가 "묶음이 한 쪽에 순서대로 들어갔나"를 검사하고 AI가 어기면 고칠 수 있다. 테마 안내문의 "비슷한 컷은 1장만"은 "연속 컷 묶음은 예외"로 바꾼다.
- **쪽 예산**: 많이 찍은 장면에 더 많은 쪽. 지금 /layout에 가는 "여행의 흐름"에 장면마다 "5장 · 2~3쪽"을 붙이면, 많이 찍은 곳이 책에서도 길어지는 것이 규칙으로 보장된다.
- **표지 후보**: 최종 AI가 3장을 직접 고른다(지금은 점수 1등을 쓴다).
- **자르는 중심**: 얼굴 상자가 있으면 그것으로(지금은 AI가 어림한다) → 머리 잘림이 줄어든다.

**권하는 뼈대 (24쪽·40장·3~4일)**
```
표지 → 가는 길 + 첫 넓은 풍경(꽉 찬 쪽) [+ 다닌 길 그림]
→ 날마다:  여는 쪽(넓게)
           → 그날 가장 많이 찍은 곳 2~3쪽: 꽉 찬 1 → 여러 장 묶음 1 → 두 사람 짝 1
           → 작은 장면들 한 쪽에 모음 → 먹은 것 쪽(날마다, 짧은 책은 책에 1~2번)
→ 가운데쯤 네 컷 쪽 1~2번 (쉼표)
→ 닫기: 같이 찍은 사진 크게 → 숫자 쪽·다닌 곳 → 조용한 마지막 한 장 + 글
```
박자 규칙은 지금 안내문 그대로 둔다(꽉 찬 쪽 다음엔 여러 장, 같은 틀 3연속 금지, 가장 화려한 컷으로 끝내지 않기).

## 4. 만드는 동안 화면

지금: 가짜 쪽 6장이 떨어지고, 4단계 체크가 0·20·50·85초에 시간으로 넘어간다. 실제 진행과 무관하다.

**1단계 (서버 변경 없음)**
- **표지부터**: 고른 테마 + 표지 사진 + 임시 제목으로 표지를 크게 먼저 보여 준다. "이 책을 만들고 있어요".
- **이미 있는 진짜 글**: 고르기 AI가 날마다 써 둔 한 줄이 책에 저장돼 있다. "둘째 날 — (그 한 줄)"과 그날 고른 사진이 천천히 넘어간다. 내 여행의 진짜 내용이라 지루하지 않다.
- **기다리며 제목 짓기**: "제목을 지어 볼래요? 비워 두면 알아서 지어요". 지금 코드는 표지 글을 AI 답에서 가져오므로, 직접 쓴 제목을 표지에 넣는 한 줄이 필요하다.
- 시간은 "보통 1~2분"(실측 중앙값) + 지난 시간 막대. 가짜 단계 체크는 지운다.

**2단계 (Worker가 AI 답을 흘려 받음)**
- AI 답은 제목 → 표지 → 1쪽 → 2쪽 순으로 온다. Worker가 완성된 쪽까지 저장하고, 앱이 물어볼 때마다 돌려준다 → **실제 쪽이 하나씩 책 모양으로 쌓인다**. 진행률 = 온 쪽 수 ÷ 예상 쪽 수.
- 검사 뒤 다시 엮는 경우가 있으니 "초안"이라고 표시하고, 다 되면 표지로 돌아가 [펼쳐 보기] 버튼을 낸다(자동으로 넘기지 않는다 — 보상의 순간은 직접 연다).

**나가면** (이미 있음: 진행 알림 + 서버 작업 + "다 됐어요"): 알림에 표지 그림과 책 제목을 넣고, 책장의 그 자리에 진행 고리를 둔다.

통과 기준은 그대로: 운영자가 같은 여행으로 다시 만들어 보고 "다른 여행도 만들고 싶다". 1단계가 끝나면 한 번 확인받고, 그 반응을 보고 4단계(추가 원가)를 넣을지 정한다.
